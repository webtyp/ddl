# ddl
<img src="docs/img/badges.svg">

## Why This Exists

Every module migrates its own tables with one call, `Sync`, and nobody writes migration files. `ddl` executes that
schema work at runtime over [webtyp/storage](https://github.com/webtyp/storage); the SQL is rendered by each backend
([design](docs/ARCHITECTURE.md), [how Sync decides, branch by branch](docs/diagrams/SYNC_FLOW.md)).

| Without `ddl` | With `ddl` |
|---|---|
| A migration file per change, written by hand | `Sync(&Model{})` creates the table, adds new columns, renames declared ones |
| A field removed from a model either drops its data blindly or stays silently | `Sync` keeps a column with data; [`Leftovers`](docs/diagrams/LEFTOVERS_FLOW.md) lists it and `DropColumn` removes it when a person decides |

## Before You Start

- A backend that implements `ddl.Compiler`: [webtyp.com/postgres](https://github.com/webtyp/postgres) or
  [webtyp.com/sqlt](https://github.com/webtyp/sqlt). Its connection also gives `Compile` and `Query` (needed to look at data).
- Models generated by `ormc` (`model.Model`).

## Step-by-Step Guide

**1. A module migrates its tables** — the whole body of its `migrate/` package:

```go
package migrate

import (
	"webtyp.com/ddl"

	calendar "github.com/veltylabs/business_calendar"
)

func Migrate(conn ddl.Execer, compiler ddl.Compiler) error {
	return ddl.New(conn, compiler).Sync(&calendar.BusinessHours{}, &calendar.Holiday{})
}
```

**2. List the columns that stayed because they hold data** — what `webtyp dev` shows before asking:

```go
package main

import (
	"log"

	"webtyp.com/ddl"
	"webtyp.com/postgres"

	calendarmigrate "github.com/veltylabs/business_calendar/migrate"
)

func main() {
	conn, err := postgres.Open("postgres://localhost/app")
	if err != nil {
		log.Fatal(err)
	}
	compiler := conn.(ddl.Compiler)
	schema := ddl.Schema{ // an app's generated config.Schema
		Steps:   []ddl.Step{{Name: "business_calendar", Run: calendarmigrate.Migrate}},
		Removed: []ddl.Removed{{Table: "work_calendar_config", Column: "timezone", Note: "moved to config.App.Zone"}},
	}
	tables, err := ddl.Capture(schema.Steps) // which models each step creates, without touching the database
	if err != nil {
		log.Fatal(err)
	}
	left, err := ddl.New(conn, compiler).Leftovers(tables, schema.Removed)
	if err != nil {
		log.Fatal(err)
	}
	for _, l := range left {
		log.Println(l.Table, l.Column, l.Rows, l.More, l.Samples, l.Removed.Note)
	}
}
```

`Capture` is also what `webtyp.com/erd` draws as the app's database
diagram ([capture.go](capture.go)); limits and fields of a leftover: [leftovers.go](leftovers.go).

**3. Act on one column, only by a person's decision:**

```go
db := ddl.New(conn, compiler)
err := db.CopyColumn(ddl.Removed{Table: "holiday", Column: "label", MovedTo: "name"}) // fills name where it is NULL
err = db.DropColumn("holiday", "label")                                               // drops it, data included
```

**4. Read any engine's backup the same way.** `ddl.BackupFormat.OpenBackup(path)` returns a read-only `ddl.Snapshot`:
its tables and columns, each table's rows as text, and `Notices` about what the engine tolerated
([backup.go](backup.go)). Implemented by `webtyp.com/postgres`; used by `webtyp.com/dataimport`.
